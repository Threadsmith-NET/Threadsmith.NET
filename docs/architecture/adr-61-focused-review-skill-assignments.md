# ADR-61 — Explicit focused review skill assignments

Status: Accepted

## Decision

An explicit, verified invocation of the shipped public `review` workflow is an additional narrow child-launch entry to ADR-57. Its `request-review` step must match the compiled recipe, exact public manifest and deployed location. The admitted workflow invokes the ordinary `delegate_agents` tool through the central invocation pipeline with a non-serialized host binding for its prepared plan. Unbound `delegate_agents` calls retain their model-origin and exact tool-snapshot guards. No other workflow action, role, task text, restored session or package named `review` grants this entry.

Four assignment-only native packages ship under `ReviewSkills`, outside the public catalogs. Native parsing, confinement, content hashing, trust/revocation and schema validation remain authoritative. A compiled recipe pins their manifests, procedures and assets. App composes Skills and Execution through Core contracts; neither implementation depends on the other.

Focused children use the existing role/model selection, scheduler and child model loop. Only a valid host binding adds private procedure content and an optional completion policy. Ordinary responses, including empty strings, retain `agent-response/1` semantics. Each focused context starts from the captured target, explicit instructions and requirements, with no parent evidence or conversation. A confined snapshot reader replaces live inspection; reviewers cannot execute processes or access a network. Git acquisition uses the registered `git_fetch` tool through the same policy, process, lifecycle, and rendering boundaries. It fetches branch tips at depth one, with no tags or checkout. Its cache authority belongs to the host workflow, so the shared `RequiresHostBinding` gate excludes it from model discovery and rejects unbound execution. Snapshot context is confined to that cache; no acquired-repository authority is inherited by reviewers.

The target captures committed and dirty local content or isolated remote Git objects. Without a remote base, review is a snapshot audit. For local and remote comparisons, ordinary `git_diff` first returns changed-path metadata for the requested scope. Local capture adds untracked paths from metadata-only `git_show` inventory; staged additions remain included from the comparison. Full `git_show` inventories and content reads then cover only changed paths, ancestor instructions, and requested requirements. Local governing instruction files are read even when Git ignores them. Mode-only changes remain in frozen scope with their Git mode transition exposed by the existing snapshot reader. Scope is applied before configured diff-entry limits. Required capture and delegation tools are checked before acquisition. Requirements default to the invoking workspace and retain every explicit criterion. Static review cannot attest runtime/manual acceptance. Deterministic synthesis preserves validated confidence, specialist details, evidence and uncertainty; only fully equivalent issues are deduplicated. Escaped private definitions are decoded before the existing leak check. Remote frozen paths retain current lexical grants without traversing unrelated invoking-checkout links; a dedicated formatter owns the fixed Markdown layout.

Versioned review records reside in host-managed review storage, separately from public skill checkpoints. Launch and delegation tool invocation identities are written before dispatch. Non-serialized host bindings live on the individual tool request/execution context and are never copied to child invocation authority. Interrupted inference is never restarted on resume; durable completed children can be joined and delivery retried without model calls. No exactly-once inference guarantee is made. Reports publish atomically into an existing authorized invoking-repository `.inbox`, or use canonical console output when absent. This does not authorize directory creation, code changes or remote publication.

## Consequences

Native/Claude skills and ordinary role replies keep their prior contracts. Private definitions never enter public discovery or joined results. Schema and citation validation establish structure and provenance, not correctness. Partial coverage remains explicit when at least one reviewer returns a validated result. Zero validated reviewers produce a failed skill and diagnostic report. The common tool envelope retains failure output/receipts while publishing a failed terminal event, so manual and model skill invocations render consistently. Provider failures retain bounded, centrally sanitized messages in existing child outcomes. Public delegation summaries withhold private focused-response JSON; the workflow joins it from the existing durable coordinator checkpoint. Broader CI, PR-provider, SARIF and finding-lifecycle work remains owned by Plan 60.
