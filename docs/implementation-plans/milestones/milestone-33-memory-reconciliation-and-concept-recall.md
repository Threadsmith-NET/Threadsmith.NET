# Milestone 33 — Memory reconciliation and concept recall

Current lifecycle status is owned by the [milestone index](../milestones.md).

## Objective

Give manual/model memory writes an explicit collision decision and discover relevant notes during ordinary tool continuations using bounded concept hints.

## Deliverables

- Shared direct-query search, both-type reconciliation, revision-specific resolution and transactional add fencing.
- Managed kind and relational concepts with compatible migration and exact/optional fuzzy discovery.
- Existing native tool pipeline transport and run-scoped progressive recall through the existing context assembler.
- Behavioral/schema/migration regression coverage, shipped-model ranking evaluation, native release validation and maintained operator procedures.

## Capability prerequisites

M3 supplies tool admission/execution; M15 owns release payloads; M25 supplies repository memory and its managed-memory maintenance contract; M29 supplies deployed prompt assets. Local embedding/reranking and active-turn continuation contracts must be available.

## Exit criteria

Both origins and both memory types reconcile without unresolved writes or stale overwrites. Superseding preserves identity; explicit distinctness preserves the original. Concepts reach ordinary continuations within existing budgets and state boundaries without another generative call. Automated and live evidence, held-out ranking-quality evidence and native load/query evidence for all six RIDs satisfy the [implementation plan](../threadsmith-memory-reconciliation-concept-recall-implementation-plan.md).

## Boundaries

No automatic writes, inferred tool-result concepts, new tool pipeline, supersession graph or durable cross-run hints. Completed memory milestone contracts stay frozen.
