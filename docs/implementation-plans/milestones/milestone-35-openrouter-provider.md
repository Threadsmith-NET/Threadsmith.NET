# Milestone 35 — Manually configured OpenRouter provider

Current lifecycle status is owned by the [milestone index](../milestones.md).

## Objective

Use explicitly configured OpenRouter models through the existing governed MAIN, child and helper request lifecycle.

## Deliverables

- Typed manual catalogs, secrets authentication and a compiled fixed authority.
- A subclass of the OpenAI-compatible adapter with one shared transport lifecycle.
- Capability-aware reasoning controls, private structured replay, tools, images, caching and usage accounting.
- Deterministic regression evidence and representative bounded live checks.

## Capability prerequisites

M7.3 compiled providers, M16 reasoning controls, M19 canonical requests/cache, M30 transient protocol replay, and M34 image inputs.

## Exit criteria

The implementation plan's applicable parity matrix passes through existing host entry points. Tool exchanges preserve exact private state without repeated effects or diagnostic disclosure. Capacity and budgets remain conservative; reported charges have explicit provenance. Representative remote checks establish exact model/upstream compatibility and document limitations separately from fixture evidence.

## Boundaries

No SDK, automatic discovery, new orchestration loop, secret/replay store, dynamic model router, or default selection mechanism. Unsupported remote functionality is accurately declared; missing host integration is not an upstream limitation.
