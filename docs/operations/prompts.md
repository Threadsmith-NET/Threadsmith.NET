# Deployed prompt assets

Source edits use stable conversation instructions and the registered `edit_source` tool. Exact diff authorization and source preconditions remain host-owned. Incremental compiler findings are advisory and independent of final build/test validation.

`Tool-write_file-Description.md`, `System-SystemPrompt.md`, and `System-ConversationGuidance.md` route report/data saves through the direct allowlisted writer. `useLastResponse:true` copies the previous archived answer without regeneration. These assets describe existing authority; only code and `tools.writeFile.allowedFolders` control writable locations.

Threadsmith ships its host-authored, model-facing prose as UTF-8 Markdown files. Source assets stay under the owning project's `Prompts/` directory and every build, publish, archive, and installer flattens the declared catalog into `<application-directory>/prompts/`. The application loads the complete catalog once during startup and then serves an immutable in-memory snapshot; it does not stat, reread, watch, or hot-reload these files.

`Tool-web_search-Description.md` and `Tool-web_fetch-Description.md` explain that search-result hostnames are pre-authorized for public HTTPS fetches during the producing run, whether the model supplies an opaque reference or a raw URL. The fetch description also identifies session-approved and saved user hostnames as pre-authorized. Other direct URLs still need an existing grant or approval. The search description also lists the four canonical arguments, their limits/defaults, locale and freshness semantics, and a valid JSON invocation example. These assets describe code-enforced validation and authority; editing their wording cannot change argument bounds or grant hostname access.

## Safe customization

`Tool-pr_fetch-Description.md` defines the required `kind` values `inventory` and `diff`, explains single-call capture with internal provider pagination and bounded delivery through `snapshotId` and line/column continuation, and states when account clarification is required. `Skill-Review.md` uses one `kind:"diff"` call to capture inventory and diff in the lead review before delegating the snapshot ID; specialists read bounded portions. Host selection reads configured account URL patterns, which are not rendered into the prompt. The `Providers` token lists enabled account IDs, adapter types and hosts for explicit selection; wording cannot change retrieval scope, routing or credential authority.

`Tool-jira-Description.md` defines the required `kind:"read"`, supported issue key/browse-URL inputs, account clarification, description coverage, and requested assistant display. Its `Providers` token lists enabled account IDs and canonical Jira site hosts only. Aliases, emails, secret references and token values are never rendered; wording cannot change routing, scopes, permissions or credential authority.

Back up any local experiment before editing a deployed prompt. Edit only the file body and retain every declared `{{TokenName}}` shown in the catalog below. Token replacement is one-pass and non-executable: assets cannot add tools, change schemas or tool availability, approve or apply mutations, widen repository or child-agent authority, alter trust, select a model, grant network or secret access, or bypass host validation. Repository `AGENTS.md` and [project prompt appends](project-prompt-append.md) remain separate untrusted inputs with their existing precedence.

Restart Threadsmith after an edit. Changes made while a process is running do not affect that process. Startup fails before model or tool activity when a required file is missing, unreadable, invalid UTF-8, contains NUL, is a link/reparse point, escapes the flat catalog, has an undeclared or unresolved template token, exceeds 128 KiB, causes the catalog to exceed 4 MiB, or collides case-insensitively with another declared filename. Unknown extra files are ignored and cannot be requested by consumers. The default catalog contains 285 prompt files; the per-file and aggregate limits apply to every deployed copy.

Prompt content is sent to the configured model provider whenever the corresponding request path uses it. Do not put credentials, personal data, or other secrets in these files. Ordinary startup, request, telemetry, event, and diagnostic output records only bounded metadata such as filename, size, digest, character count, or token count—not prompt bodies or rendered token values. Explicit `--raw-model-log` output is a privileged diagnostic and intentionally contains the complete provider-visible request, including externalized system/context messages, tool descriptions, tool results, and provider instructions. Protect and delete raw logs accordingly.

All rendered prompt content counts against the selected model's normal request capacity. A compiled provider registration can declare one cataloged provider-instruction asset; the effective catalog carries that declaration onto its projected profiles, and the shared resolver loads it without provider-specific routing. Native Codex currently declares such an asset. Provider instructions are attached to the provider-neutral request before admission, appear as a dedicated instruction contribution in wire/context inspection, and can reduce the room available for other context. A request that cannot fit the exact instructions, fixed framing, tools, and output reserve fails before network dispatch.

Upgrades replace the prompt defaults contained in an installed application payload; Threadsmith does not merge local edits. Copy experiments elsewhere before upgrading and reapply them deliberately against the new catalog. A partial copied catalog is not supported.

## Ordinary delegated children

The repository-inspection descriptions and shared `System-RepositoryInspection.md` prefer compiler-backed semantic tools for C# discovery and relationships. `code_explore` is the preferred starting point for broader repository understanding, architecture, debugging, execution flow, and cross-file impact; known files and symbols are useful anchors, not reasons to avoid it. Granular semantic tools handle specific declarations and relationships. Direct `read_file` remains appropriate for isolated file-content questions and local edits; scoped `search` handles exact text without semantic relationships. Returned source counts as already read and should be reused. Parent and child agents receive the same focused exploration, batching, evidence reuse, and completion guidance. Semantic evidence must match the reviewed revision; another revision requires ref-based evidence. These wording changes preserve tool validation, permissions, and path policy.

Every ordinary child receives the common child host policy followed by a role-specific system amendment. The amendment steers the activity; the host still selects the model and available tools and enforces permissions and cancellation. Repository instructions, task context, and evidence retain their separate trusted framing. Answers have no required fields, citation identifiers, JSON envelope, or role-format correction rounds. Technical tool-argument errors can still receive corrective feedback.

The joined `Tool-delegate_agents-ChildSummary.md` block uses `Summary` for the full, unparsed ordinary response string, including an empty response, or the legacy summary for an older outcome. The surrounding result envelope remains host-owned metadata. Separately approved mutation preparation retains its own protocol. The original Explorer output-policy and format-correction files remain in the deployed catalog but are not sent on the ordinary child path.

`Context-ChildAgent-Task.md` labels `BaselineIdentity` as a Threadsmith workspace fingerprint, not a Git revision. `Tool-delegate_agents-Description.md` explains concurrent assignments, sequential calls within one response batch, inherited tools, explicit `readOnly`, and shared-workspace coordination. `System-ChildAgent-HostPolicy.md` directs children to use their advertised tools under the parent's scope and permissions. Tool metadata excludes both `delegate_agents` and `invoke_skill` from child catalogs. `System-ChildAgent-Implementer.md` guides implementation and validation through the remaining tools and distinguishes completed work from suggestions. Editing these prompts does not change scheduling, permissions, or baseline validation.

## Catalog

The `code_explore` omissions block includes unresolved requested filenames, their resolution outcomes, and any permitted path alternatives. These values come from the tool result; they are not guesses made by the model or permission to read additional paths.

The repository-inspection guidance, `code_explore` description, partial-source action, source-line retry reason, and continuation cursor label make follow-up conditional on an outstanding question requiring the omitted evidence. An incomplete result alone does not require another call. Exact source cursors retain their source identity checks and use configured source allowances without discovery-tier reductions; their presentation omits selected-evidence repetition.

The token column lists required, case-sensitive named tokens unless a token is marked optional. `None` means the file is loaded as exact text and must not contain a template marker. Every source owner path is `src/<owner>/Prompts/<filename>`; every deployed path is the flat `prompts/<filename>` path shown here.

For a category-organized explanation of every file and a glossary defining what every placeholder means, see the [Prompt file reference](../prompt-file-reference.md).
