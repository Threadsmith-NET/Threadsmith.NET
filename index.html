Reasoning meets engineering

A good answer is a start.
A validated change is the goal.

The model proposes. The host owns the change lifecycle. Compiler-backed, pre-build semantic validation catches problems in proposed code before it touches your repository. Affected builds and tests provide the next layer of evidence.

01 — DISCOVER

Ground the request.

Inspect the solution and gather semantic evidence when build trust permits. Use text-based discovery when it doesn't.

02 — PLAN & SCREEN

Check before you change.

Review the plan, then screen proposed C# changes with in-memory syntax and semantic checks before staging or approval.

03 — APPLY

See what will change.

Stage mutations, inspect the exact diff, check the baseline, and apply authorized changes transactionally.

04 — VALIDATE

Close the feedback loop.

Use affected-project builds, targeted tests, and normalized diagnostics to verify results and guide corrections.

Semantic screening depends on workspace confidence and does not replace builds, tests, analyzers, or source generators. This lifecycle covers host-managed mutations. Approved external processes can have direct filesystem effects; trust and tool policies still matter.

In development

Still on the anvil.

More control. More ways to connect. More room to make Threadsmith your own. Here's what's taking shape next.

  • 01

    Process control, your way.

    Finer control over which processes the agent can run. Lock it down or leave it wide open—your call.

  • 02

    A public API for your workflows.

    Run headless Threadsmith from any .NET application or drive it through external automation.

  • 03

    More events. Richer extensions.

    Expand the Extension API with access to a broader set of domain events, so integrations can respond to more of the workflow.

  • 04

    Sharper agent roles.

    Further refine subagents and their roles, with clearer responsibilities and better coordination.

  • 05

    Keep pushing code_explore.

    Continue refining natural-language code exploration and the evidence it brings back to the model.

  • 06

    Diagrams in the terminal.

    Bring Mermaid diagram support directly into the TUI to make relationships and flows easier to follow.

  • 07

    Beyond text.

    Add multimodal input and output to bring more kinds of context and responses into the conversation.

  • 08

    Prompts that fit the model.

    Optional model-specific prompts and tool descriptions, tailored to the nuances of current and future models.
