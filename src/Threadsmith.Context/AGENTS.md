# AGENTS.md — Threadsmith.Context

## Purpose

Own phase-specific evidence governance, bounded cross-turn conversation memory, active-turn continuation compaction contracts/validation, repository-scoped memory policy, model-context assembly, prompt assets, and per-request model resolution.

## Ownership

- EvidenceStore.cs — attributable session-scoped evidence, clone copying, and turn-boundary invalidation.
- ContextAssembler.cs — phase policy, three-mode conversation assembly, repository-memory retrieval, deterministic pressure reduction, token estimation, request-local source-frontier inspection, telemetry, and inspection records.
- ContextContracts.cs - context assembly requests and results, including the explicit approved-child capacity deferral contract.
- ConversationMemory.cs — authoritative promotion, strict structured-summary validation, bounded completed-turn compaction, deterministic retrieval, and repository-aware invalidation.
- ActiveTurnCompaction.cs — host reliability bounds, complete continuation groups/source references, model-backed cumulative candidates, strict low-authority validation, in-memory checkpoints, and deterministic summary projection.
- RepositoryMemory.cs — explicit repository-memory command policy, user-authored provenance, bounds, supersession, forget, conservative mutation invalidation, deterministic local validation outcomes, and durable mutation receipts for truthful audit publication.
- PromptAppendLoader.cs — confined, sanitized, bounded, strict-UTF-8 repository prompt assets re-fingerprinted at each turn boundary.
- DeployedPromptLoader.cs — eager atomic loading, strict named-token validation/rendering, safe metadata/digests, and immutable process-lifetime access to the complete application prompt catalog.
- `Prompts/` — stable system policy, phase/output instructions, governed/legacy context framing, and active-turn compaction/summary prose.
- RepositoryInstructionResolver.cs — bounded root-to-scope `AGENTS.md` plus prompt-append bundle resolution, content identity, and invalidation.
- ModelResolver.cs — host-controlled configured-profile selection with advisory hint snapshots.
- AgentContext.cs - child evidence assembly and legacy structured complete-batch finding admission with assignment, role, baseline, citation, and model provenance checks; ordinary response bodies are not promoted to findings.

## Local Contracts

- Always preserve the sanitized current turn. Native user/assistant messages retain sanitized plain text without XML entity encoding; escaping applies only to the legacy XML rendering. In Conversation-aware mode, admit only bounded complete recent turns plus provenance-linked structured/retrieved memory; Governed-memory-only excludes raw prior messages; Stateless excludes every prior-turn category.
- Stable host policy precedes the untrusted content-addressed repository instruction bundle, which precedes phase instructions. It prefers applicable semantic tools for repository-wide C# discovery and compiler-backed relationships, while known-file reads and file-scoped text searches can proceed directly. Reuse sufficient evidence without redundant retrieval. Evidence-collection guidance tells the model Threadsmith has fast host-native inspection tools and should batch independent read-only inspections in one response, prefer structural/semantic/index tools over broad text search or raw line slices where applicable, batch independent symbol/source lookups, merge adjacent same-file ranges into the fewest relevant raw reads, and avoid serial one-search/one-symbol/one-file or adjacent narrow read loops. Once target, applicable instructions, and material impact resolve a requested repository change without a correctness ambiguity, stop tool exploration and call `propose_plan` rather than investigate unrelated patterns or references. Read-only exploration, audits, explanations, and diagnostics should answer directly from gathered evidence instead of manufacturing a plan. The execution host advertises inspection tools for the full model-round budget by default; context guidance must preserve the direct-answer path for read-only work, while remaining compatible with the optional positive `execution:maxPlanningToolRounds` cutoff. Resolve applicable `AGENTS.md` parent-to-child from the canonical root to working scope; configured prompt appends follow with distinct provenance.
- Decisions outrank relevance during reduction. Stale, phase-ineligible, duplicate, and over-budget evidence is omitted with an inspectable reason.
- Context includes session-wide evidence plus evidence owned by the current run; run-specific evidence never crosses run boundaries. Equal-ranked evidence orders oldest-first for append stability and serializes content identity with complete provenance but no incidental timestamp. Delegated child context contains only the frozen assignment, immutable baseline, eligible governed evidence, and explicit child tool ids, never parent/sibling transcripts; non-sensitive assignments omit sensitive evidence before assembly. Ordinary final bodies live in `AgentRunOutcome.Response` and may contain any text, JSON, or an empty reply. Do not parse them into findings or promote their claims to verified parent evidence. Legacy structured findings still require schema, identity, generation, bounds, and citations from that exact context or the owning child's admitted tool evidence, never unrelated session evidence. Admit legacy findings only after the durable joined checkpoint: validate the complete set, prepare one ordered event batch under caller cancellation, and atomically commit the complete parent-evidence batch before subscribers observe it. Pre-commit failure or cancellation leaves the store unchanged; later subscriber failure cannot roll committed evidence back or revoke the joined result. Record child/assignment/effective-model/baseline provenance independently of response contents.
- Apply queued evidence invalidations only at the owning session's turn boundary. Repository-derived evidence depends on `repository`; compiler-aware evidence also depends on `semantic`.
- Evidence storage uses Core's JSON-aware sanitizer for valid structured content and ordinary text sanitization otherwise. Redact values without corrupting JSON syntax; preserve already-sanitized formatting so child evidence retrieval matches the delivered result.
- Session clones receive detached evidence records under the destination session while preserving stable evidence identity and provenance links; source and clone entries remain independently invalidatable.
- Re-fingerprint applicable prompt append and `AGENTS.md` snapshots at every turn boundary independently of watcher delivery. Cache only identical digests; reject reparse traversal, malformed UTF-8, bounds violations, prohibited paths, and files changed during their read.
- Deployed host prompt assets are distinct from repository instructions and prompt appends. Load the code-declared flat catalog once from the supplied application base, reject missing/invalid/linked/colliding/oversized assets atomically, publish no partial cache, and perform no prompt filesystem access after initialization. Rendering substitutes only declared named tokens once and never interprets values recursively.
- Plan revision assembly includes the pending plan as explicit governed state alongside the revision instructions. Current-turn host context is request-local governed state only: it may inform the current model request but must never mutate `TaskSpecification`, enter conversation promotion, or survive restoration. Request-local additional host-owned `ModelMessage` values, such as bounded corrective messages, are sanitized, appended to the assembled request, included in structured wire estimates, and budgeted before optional evidence is retained.
- Implementation/correction assembly includes the accepted plan, immutable diagnostic-baseline facts, and current promoted mutation-baseline identity/hashes; selects `CodeEdit`; advertises only eligible bounded read tools plus proposal-only `propose_mutations`; and requires one plan-step-correlated envelope without staging or authorization. The model supplies only approved step ids and closed change content; mutation guidance must name canonical fields (`mutationSet.rationale`, mutation item `type`, `relativePath`, and `baselineSha256`) and reject plan/legacy synonyms (`kind`, `path`, `baselineHash`, and per-item prose fields). The host assigns all execution, baseline, set, and mutation identities before validation. `RenameSymbol` is preferred for C# symbol renames when semantic symbol evidence is available, with declaration-file renames represented separately as `MoveFile`; `ReplaceText` requires exact expected text, and offsets remain exact when correct and may be host-relocated only for one unique match in rolling immutable/staged content. Proposal validation must reject every returned mutation source or lifecycle destination whose normalized path is not in that accepted-plan schema-2 file-intent path set before staging.
- User/session model defaults win over hints. Hints may name only configured profiles and cannot relax capability, sensitivity, or budget constraints.
- `ContextAssemblyRequest.DeferAgentModelCapacityValidation` defaults to `false`. Only the approved preparation host may set it, during `ImplementationModelTurn` or `CorrectionModelTurn` with both `ApprovedPlan` and `MutationBaseline`; other uses fail before assembly. With the flag set, preserve the complete provisionally admitted context for the mandatory agent selector. Defer selected-profile pressure reduction and every final selected-profile fit check, including complete provider wire input. Existing provisional admission bounds, phase/sensitivity policy, sanitization, and source eligibility still apply. The returned context and inspection are provisional, not permission to dispatch. `MutationProposalApplication` must pass the complete request through `AgentModelSelector.SelectForRequest` before provider I/O, using the candidate profile's own output reserve. After fallback, rebuild context, provider instructions, output limits, and wire estimates, then recheck. Incompatible or unstable selection fails before I/O. This is an internal host contract, never a repository setting or model argument. Ordinary assembly retains its existing reduction and capacity checks.
- Conversation candidates are untrusted until schema, bounds, sensitivity, message/run/evidence provenance, repository revision, authority, and supersession validation pass. Failed or cancelled compaction leaves the prior snapshot active.
- Active-turn compaction is separate from durable completed-turn memory: only a complete previously delivered oldest tool-call/result prefix is eligible; the newest raw groups and frozen authority/current-user context stay exact. Main-profile pressure and emergency capacity remain independent from candidate generation. Candidate input shares one aggregate budget scaled to an optional trusted separately configured `Summary` profile, or the active main profile when none is configured. The candidate profile owns routing, context/reserve, maximum output, reasoning, timeout, retry, cost, and sensitivity; advertises no tools; receives required-first bounded task/acceptance intent, the complete previous active-turn summary when present, selected raw tool activity, and host-observed file lists; and returns one completed Markdown checkpoint. The host validates schema, exact cumulative covered group range, host file lists, sanitization, and authority markers; strips model-emitted file-list sections and appends host-owned file lists. Unclassified tool-result groups are conservatively repository-sensitive at the auxiliary boundary. Sensitive or request-cost-incompatible input is rejected before candidate hooks/I/O when the configured profile cannot receive it. One candidate descriptor frozen on the request owns provider dispatch, hook workload, telemetry, inspection, and activity identity. Validated output projects as one explicitly non-authoritative historical assistant summary and never becomes durable memory; activation requires positive rebuilt-request savings, not a fixed pressure target. The ordinary loop retains only bounded in-memory checkpoint metadata while original events/evidence remain authoritative. Request-local visible source frontiers are derived only from structurally complete host-sanitized `code_explore` tool results that remain in the canonical model request after reduction; summaries, archived evidence, provider history, malformed or reduced partial JSON, and compacted-away tool results do not prove source visibility.
- Repository-scoped memory commands accept only explicit host-command input, sanitize and bound text before persistence, attach user-command provenance, preserve superseded/forgotten audit rows, and never treat repository-authored files as memory authority. Host-observed mutations conservatively mark path/symbol/project/revision-scoped active memory stale; independent explicit user memory remains active. Context assembly selects only active repository memory with deterministic authority/relevance ranking, item/token budgets, sensitivity propagation, and inspection rationale for included and omitted items.
- Direct authoritative promotion applies the same configured per-item and active-item bounds through one serialized atomic persistence operation; overflow remains inspectable as inactive memory instead of making later assembly unbounded. Rendered repository-memory framing and metadata count against the retrieval token budget. Automatic memory must meet the configured exact-token relevance floor and creation-age maximum; duplicate observations do not extend eligibility without new durable provenance. Explicit user-authored memory is exempt from both admission gates.
- Explicit user requirements/decisions/constraints survive pressure ahead of raw history, lower-ranked retrieval, repository findings, and completed-work memory. Stale/superseded items remain auditable but are not selected.
- Included archived messages and memory provenance participate in sensitive-data model constraints. For ordinary assembly, bound provisional evidence admission by the configured catalog's largest input capacity, resolve the request profile exactly once from that bounded candidate set, then reduce final assembly to the selected profile's configured context window minus its effective request output-token reserve, which remains distinct from the provider hard maximum. `ContextAssemblerOptions.MaximumTokens` is fallback-only when no configured model resolver exists and is never a shared cap across configured profiles. Context inspection records calculate pressure against the selected model profile's full window and contain its effective input budget, mode/source, message and memory decisions, provenance/rationale, snapshot range/version, pressure/reductions, and no provider SDK or extension implementation types; records use the bounded least-recently-used cache (256 runs by default) and are invalidated through the shared model-selection command boundary when the active profile changes.
- `System-SystemPrompt.md` contains the brief cache-stable preference for the maintained documentation skill. It names only the existing conditional `invoke_skill` path and never embeds the documentation bundle in ordinary context.

## Work Guidance

- Main and child active-turn retention use their configured recent-token allowance directly, rounding up to whole exchanges. Request-size tuning targets, fixed context, and summary allowances must not shrink it. Keep real model-capacity admission and emergency handling separate; do not activate a replacement without the required savings.
- Main and child compaction consume the same optional global candidate profile/reasoning descriptor supplied by App. Candidate context, output reserve, sensitivity, provider instructions, and reasoning come from that descriptor, while pressure remains tied to the task model. Omitting the descriptor preserves each loop's own model fallback.

- Ordinary children reuse active-turn compaction contracts, complete-prefix selection, candidate generation, validation, and summary formatting with independent request-size tuning. Their instructions, assignment, and steering are not eligible for replacement. Inherited evidence becomes an ordinary compactable history group only after the child has received it verbatim; its original IDs remain retrievable. The summarizer receives the complete canonical child assignment message as task data, including supplied context and tasks; it counts toward candidate input capacity without objective-length clipping. Summary allowances control requested model output, never synthetic character or estimated-output rejection. Preserve provider stream controls, incomplete-output rejection, and rebuilt-request savings and capacity checks. Preserve useful evidence-ID associations in working notes without imposing a final-answer format. Original tool results remain in the evidence store; child lookup checks previously delivered IDs and staleness.

- For every model-callable delegated role, preserve every policy-eligible parent evidence item and every resolved instruction source; never reduce them to fit a synthetic cumulative token budget.
- Ordinary role amendments guide work without required response fields, citation GUIDs, semantic grading, or response-format repair. Keep delivered-evidence citation checks for legacy structured admission and actual approved mutation validation separate from unrestricted ordinary replies. Tool evidence, sensitivity classification, context accounting, actual request capacity, and frozen authority still apply. Retain configured/effective provider/profile/reasoning, selection source, and fallback provenance independently of body claims; trusted model routing belongs in Models/App.
- Keep prompt append paths inside the repository, reject prohibited paths and reparse traversal, and preserve configured order.
- Treat repository evidence and append content as untrusted data.
- Sanitize every free-text task field at assembly while preserving already-validated repository-relative plan paths.
- Add evidence categories and phase rules together, with focused tests for inclusion and omission.
