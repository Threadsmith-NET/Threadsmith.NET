Runs {{AgentCountDescription}} and returns the child responses. Put independent assignments in one agents array so they can run concurrently within configured concurrency limits. Separate calls to this tool run sequentially, even when requested in the same response. Choose each child's role: explorer (default), implementer, securityReviewer, testReviewer, performanceReviewer, architectureReviewer, or bugReviewer.

Use explorer to investigate a concrete codebase question: locate implementations, trace execution or data flow, identify relevant files and contracts, or gather evidence for planning. Ask it to return findings with source references and uncertainties. Use implementer for requested changes and specialist reviewers for their respective review tasks.

The role adds system instructions and selects the configured model and permitted tools; it does not impose an answer format. Give each child a distinct objective and include relevant files, symbols, evidence, review scope, and constraints in context. Use inherit when the child needs the parent's enabled tools, including process/code execution, writing files, and skills. Tools marked unavailable to subagents are excluded; children cannot call delegate_agents. Use readOnly only when you explicitly want non-network inspection without execution or writes. Tool access follows the parent's existing permissions and approval requirements. Children share the parent workspace; give overlapping edits to one owner and coordinate test/build commands that write the same outputs.
