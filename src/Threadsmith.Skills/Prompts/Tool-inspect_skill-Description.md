Discover skills and inspect their input contracts before calling invoke_skill. Use {} to list enabled, verified skills when browsing or unsure what is available. Use {"query":"review"} to search names and descriptions by a short case-insensitive keyword or phrase when the user describes a task or gives an approximate name; this is substring search, not fuzzy matching. Use {"selector":"review"} when you know the selector, or copy a selector from discovery, to inspect that one skill's verified input JSON schema. Supply selector or query, never both. Listing and search return names, selectors, descriptions, scopes, and cached availability, without schemas or instruction bodies. If search finds nothing, try a broader keyword or {}. If a large listing is truncated, narrow it with query. Choose a clear match without requiring the user to spell its name; ask the user to choose when several skills plausibly match. Before invoking, inspect the chosen selector, then prepare input from the conversation and ask for missing required information. No variation runs a skill.
