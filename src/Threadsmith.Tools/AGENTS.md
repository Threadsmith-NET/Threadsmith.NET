# AGENTS.md — Threadsmith.Tools

## Purpose

Own typed tool contracts, thread-safe built-in and dynamic extension registration, centralized invocation policy, secret resolution, bounded built-in read tools, and tracked child processes.

## Ownership

- `ToolContracts.cs`, `ToolRegistry.cs`, `ToolStateManager.cs`, and `McpToolApprovalStore.cs` — public host-owned contracts, registration, effective availability, repository-scoped narrowing persistence, and repository/schema-bound user-owned MCP approval persistence.
- `ToolInvocationPipeline.cs`, `ToolBatchScheduler.cs`, and `ToolPolicy.cs` — validation, policy, approval, budget, cancellation, normalization, activity, host-owned scheduling claims, deterministic conflict waves, and bounded concurrent sibling execution.
- `BuiltInTools.cs` — file, search, Git status, semantic, and approved process tools.
- `RepositoryInventoryTools.cs` — Typed Git diff/log/show/blame/branch comparison and .NET inventory adapters over Core host boundaries.
- `NativeValidationTools.cs` — Typed NuGet health, exploratory build/analyzer/format, diagnostic query, test discovery, and targeted-test adapters.
- `AdvancedSemanticTools.cs` — Call-hierarchy, symbol-impact, closed C# pattern-search, and generated-code-query adapters.
- `NewBuiltInTools.cs` and `ToolConfig.cs` — date/time, isolated C# scripting adapter, arbitrary per-tool scalar configuration, and default-disabled availability metadata.
- `ProcessManager.cs` — bounded output, active-process tracking, timeout, process-tree cancellation, and bounded host-owned child-environment additions whose values are never logged.
- `SecretResolution.cs` — provider-neutral static-secret contracts/resolver, linked per-attempt cancellation, cancellable repository Git proof, host-aware path identity, and bounded environment/repository/user providers; `SecretStore.cs` retains lifecycle/legacy compatibility adapters.
- `WebSearch.cs`, `WebFetch.cs`, `WebFetchAuthorization.cs`, and `OutboundConsentStore.cs` — default-disabled governed external search, progressively disclosed public-HTTPS textual fetch, compiled transports/extraction, transient result/direct authorization, and user-owned repository-bound consent.

## Local Contracts

- Workspace-dependent definitions set `ToolDefinition.RequiresWorkspace`; request assembly withholds them whenever no semantic workspace identity exists. Sibling model tool calls are fully collected before execution. Schema-versioned descriptors and validated invocation-specific claims determine stable conflict-free waves; only reviewed compiled read/read tools overlap, while unknown/dynamic/approval/process/workflow/semantic calls serialize. A later call never enters an earlier wave than an ordinal-preceding call it conflicts with, and a shared pipeline source limiter enforces every compiled source maximum across concurrent batches and direct callers. Preparation failures become ordinary per-invocation validation results instead of aborting valid siblings. Fail-fast cancellation drains every started sibling and preserves its terminal result, then returns explicit cancelled terminal results for every never-admitted later call. Caller cancellation is propagated after the final wave. Results join in original model ordinal order. Every invocation goes through `IToolInvocationPipeline`; the pipeline carries the authoritative run phase into tool execution, and model output never grants approval. Delegated-worker assignment contexts resolve the frozen plan assignment, intersect parent and child allowlists and approved roots (failing closed when root scope is disjoint), preserve an explicit deny-all result for an empty child allowlist or intersection, union denylists, cap trust, remove network/process/secrets when disallowed, and identify the child requester. Hierarchical usage ledgers reject negative deltas, charge atomically, and reject exhaustion without sibling borrowing.
- Policy runs after typed validation and before implementation code. Declare all resource paths, executables, network hosts, and secret references.
- Static secret values never enter ordinary configuration or projections. Consumers use `ISecretResolver`; compiled host composition owns provider order/registration, and repository values cannot satisfy user/managed trust. Existing configured consumer identifiers retain their owning subsystem's syntax and are hash-derived into bounded, non-disclosing component IDs before resolver diagnostics. Repository JSON is read only after opened-repository-relative Git-index absence for the exact file and every applicable ancestor/store representation plus effective-ignore proof, using a no-follow, Unix-nonblocking open whose regular-file type, resolved path, and reparse attributes are validated from the same stable handle before bounded reads through that handle. User JSON requires owner-only Unix modes or current-user ownership plus a restricted Windows ACL, repeated from the opened handle. FIFOs, sockets, devices, and other non-regular targets fail closed before any read.
- Tool results and provenance are host-owned, sanitized, bounded, and durable. UI projections retain only a bounded preview. Raw argument objects and resolved secrets are not durable activity. Exception-provided process-local error detail may make a current headless result actionable, but durable completion events retain only the generic error. Every compiled built-in tool with useful validated input context must opt into one concise activity detail; omit detail only when there is genuinely no useful non-sensitive input context. The pipeline sanitizes, single-line normalizes, and rune-safely bounds it to 240 UTF-16 characters before publication. `read_file` places the resolved requested line window before the path so paged reads remain distinguishable even when a long path is truncated. `run_process` additionally masks named CLI credential switches, including whitespace-separated values, before the generic sanitizer runs. Extension and MCP arguments remain undisclosed by default.
- Recursive tools skip prohibited descendants and reparse points even when their approved starting root is broader. On Windows, recursive listing/search also skip path segments whose basename is a reserved DOS device name (`CON`, `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`, `COM1`–`COM9`, `LPT1`–`LPT9`, or the Windows-recognized `COM¹`–`COM³`/`LPT¹`–`LPT³` aliases, including extension forms) so one unopenable repository entry cannot abort the entire inspection.
- Path containment follows host filesystem case semantics: case-insensitive on Windows and case-sensitive elsewhere.
- `run_process` exposes a small model-facing `command`/`timeoutSeconds` shell schema and is conversation-available only when its configured shell is present in `tools:allowedExecutables`. It remains `ExecutesCode`, never read-only. The host advertises only supported bare shell names (`pwsh`, `powershell`, `bash`, `sh`, `zsh`, or `cmd`) resolved from trusted PATH, fixes the working directory to the repository root, and retains trust, approval, hooks, timeout/output bounds, cancellation, process-tree termination, and audit. Allowing a shell grants its complete command language, including pipelines and nested child processes; the executable allowlist governs the shell boundary and must not be described as enforcing nested command names. The ordinary conversation pipeline currently has no interactive process-approval policy, so `run_process` is advertised only when machine/user-only `tools:runProcess:requireApproval=false` removes per-call approval; with the safe default it is withheld rather than offered and predictably denied. Repository configuration cannot grant that exemption and may reimpose approval through `tools:requireApproval`, which withholds the tool from ordinary conversation.
- Process-manager timeouts are normalized as failed tool invocations with `ToolErrorClassification.Timeout`; optional standard input is written inside the tracked timeout/cancellation lifetime and is never logged.
- Built-ins repeat boundary-aware path confinement immediately before local filesystem/process access as defense in depth. Text search uses a host-owned bounded ripgrep path for case-insensitive literal, case-sensitive .NET-validated regex, and simple narrowed-glob searches, accepting the release- or development-staged app-local executable selected by App composition (or the source-development `PATH` fallback) when no configured prohibited path requires pre-read filtering. Fast and managed paths share one case-insensitive generated/dependency/Git directory exclusion set so backend availability cannot change results. The fast path also respects repository ignore rules, SQLite exclusions, hidden-file inclusion, file-size/output/timeout/cancellation bounds, and normalized provenance. Unsupported/inverted glob, prohibited-path, unavailable-ripgrep, and failed-ripgrep cases use the confined managed scanner; unavailable/failed acceleration returns a bounded model-visible warning. The managed scanner first requests Git's bounded, non-interactive, no-lock, fsmonitor-disabled `ls-files --cached --others --exclude-standard` inventory so repository ignore rules remain authoritative; if Git is unavailable or the directory is not a Git worktree, it prunes `.codegraph`, `.git`, `.idea`, `.vs`, `artifacts`, `bin`, `node_modules`, `obj`, and `TestResults`, plus ancestor/leaf symlink or reparse-point, prohibited, reserved-device, oversized-file, and SQLite inputs before reading. Git-inventoried leaves are filtered before admission and rechecked immediately before managed metadata/read access. It skips files that become locked, inaccessible, or unavailable, streams lines, and stops at the result bound.
- Model-facing descriptions make semantic selection mandatory: symbol, reference, implementation, call, impact, structural-pattern, and generated-code questions use the advertised semantic tool before `search`; text search is allowed only when no semantic tool applies or the attempted semantic tool fails or explicitly reports incomplete/degraded evidence.
- Tool-call budgets are checked without mutation before approval and accrued only after approval succeeds.
- Started invocations always receive a durable completion event; cancellation while awaiting approval also emits `ApprovalDenied`. Tool approval requests carry the closed `ToolInvocation` request kind; their action text is display metadata, not routing authority.
- Tool outputs use the host sanitizer as one complete policy; tool definitions do not carry unused field-level redaction metadata.
- Invocation telemetry spans remain argument-free and include only latency and rejection metrics. Ordinary-tool timing measures elapsed time monotonically only around `ITool.ExecuteAsync`, projects the same authoritative duration to completion events/results/telemetry, and obtains closed built-in/extension/MCP origin from immutable registry metadata rather than implementation-type inspection. Optional activity detail is presentation metadata and never a telemetry tag.
- Built-in inspection tools are read-only; mutating tools remain isolated behind the transactional mutation subsystem.
- Git and .NET inventory tools require `TrustedRead`, explicitly declare Git to executable policy, expose one typed schema per operation, retain bounded normalized provenance, and do not use `run_process` as their implementation surface. Git tool schemas use model-readable string enum values, document mode-specific revision requirements, and accept strict nullable defaultable fields only when the implementation normalizes them before Git access.
- Advanced semantic tools require `TrustedBuild`, an opened workspace, and one fenced `PartialCompilation`-or-better snapshot. They are read-only, process/network-free, declare path scope, accept only closed host schemas and explicit bounds, filter every returned location and generated-content document through invocation path policy, and project generation/confidence/provenance/completeness without treating impact as proof or executing patterns/generators.
- Native validation operations expose distinct closed schemas with no arbitrary command/property/filter forwarding. Process-backed operations declare `dotnet`, require `TrustedBuild`, and are classified `ExecutesCode`; diagnostic query remains a `TrustedRead` read-only index operation and passes the active repository identity into the retained index before path-policy projection. Configured NuGet sources come only from trusted configuration and declare every source host to network policy. Recursive Git evidence filters prohibited/narrowed-scope descendants before return; .NET inventory declares and rechecks every selected solution, project, and central-package metadata path before reading.
- `datetime` is default-enabled and trust-free beyond `UntrustedInspection`. `csharp_script` is default-disabled, non-idempotent, requires `FullyTrustedAutomation`, runs in a fresh tracked worker, and retains no state. Self-contained layouts launch the staged worker apphost directly; framework-dependent development/test layouts may fall back to `dotnet exec` for the worker DLL. Its timeout/output/import settings come from `tools:config:csharp_script`; raw code travels over bounded standard input, never command-line arguments.
- Default-disabled tools use explicit restart-safe overrides without changing the meaning of an absent `tools:enabled` allowlist. MCP tools additionally require an exact repository/profile/capability/schema approval from the owner-protected user-owned store outside repository control; repository availability settings may narrow but never grant that authority. Approval-store replacement creates the private temporary file with owner-only permissions before publication on Windows and Unix. Unsafe, malformed, unreadable, or oversized optional approval state fails closed to no approvals without blocking application startup; a later explicit enable atomically replaces it with valid private state. The worker's restrictions are defense in depth, not an operating-system sandbox.
- Tool availability is separate from invocation policy: disabled tools are neither advertised nor resolvable. Essential tools remain enabled. An explicitly empty, case-insensitively named `tools:enabled` array is a deny-all allowlist, while an absent array remains absent across toggles. Repository changes rebind both effective state and the persistence target before the open workflow completes. State changes accept the repository JSON provider's comments/trailing commas, atomically preserve unrelated `.threadsmith/config.json` content, share `RepositorySettingsCoordinator` with every other repository preference writer, and become visible in memory only after persistence succeeds.
- Extension generations validate every proxy before batch publication into the shared catalog. Every dynamic registration must supply explicit immutable built-in, extension, or MCP source metadata; registration never silently invents an unknown origin. A dynamic proxy may replace an existing dynamic tool id only when the caller identifies the exact current predecessor instance during hot replacement; unrelated active extensions and constructor-supplied built-ins cannot be replaced. Unload removes each proxy by its registered tool-definition id and only when that proxy is still current. Unloaded extension preferences remain persisted so a later reload restores the effective state.
- Brave web-search authentication requires a `UserOwned` or higher-trust secret; an ignored repository store cannot supply or override its credential. Outbound tools require ordinary availability plus a valid user-action consent record outside the repository. Consent schema 2 covers search plus retrieval; older records and records with an omitted schema fail closed. Search queries pass through the shared host secret sanitizer before HTTP, credentialed transports do not automatically follow redirects, and normalized results carry an explicit untrusted-evidence boundary and URL/query/provider provenance. Fetch-eligible search results issue bounded opaque repository references that activate `web_fetch` only for their producing session/run; valid results outside fetch URL policy remain available without a reference, and direct grants are exact and one-shot. Fetch independently validates public addresses and every redirect, admits only exact current host-owned result or invocation-group hosts without requiring static repository host configuration, pins connections to validated addresses, disables cookies/proxy/ambient credentials, and applies conservative binary-signature, control-data, and declared-media-shape sniffing before parser execution. It accepts only bounded textual media/encodings, drops active and hidden HTML regions with a cancellation-aware bounded scanner, applies parser complexity and whole-operation deadline bounds, and projects only query-free URLs plus digests. Authorization and retrieval consume one shared immutable effective-options snapshot source; repository transitions rebind repository narrowing through `ToolStateManager`, revoke prior transient routes, and rollback to the former repository limits if the open boundary fails. Immutable pipeline enforcement metadata uses the repository-excluding trusted ceiling so later repository rebinds cannot retain stale narrower limits. Repository-inclusive fetch limits may only narrow repository-excluding trusted ceilings. Consent schema 3 alone enables bounded fresh-message URL recognition (32 KiB/eight unique candidates); candidates require message-start or a supported opening/token delimiter, embedded substrings and apostrophe-ambiguous spans do not qualify, and a candidate reaching the scan boundary is rejected unless the raw message ends there, so no truncated URL prefix gains authority. It also enables opaque `userUrlId` issuance and current-run progressive activation; schema 2 retains only legacy search-result compatibility. References bind message/repository/session/run/exact digest/policy fingerprint/scope generation/expiry and consume once. Model-proposed `url` values may request one serialized exact prompt only for an already-active run; the prompt exposes origin plus only a separator-preserving `[REDACTED]` path shape, approval creates an invocation-identity grant, and unavailable/headless prompting returns `DirectAuthorizationRequired` with the sanitized origin, redacted path shape, and exact digest required for explicit authorization in only the current process-local result; its durable failure is generic. Prompt details and URL-free lifecycle notifications remain inside the process-local prompt-router attachment and never enter the shared domain stream, projections, persistence, telemetry, hooks, or restoration. Neither ergonomic route authorizes redirects or survives run/session/repository/tool/policy/options lifecycle revocation.
