Executes authorized {{ShellLanguage}} CLI commands when no dedicated tool applies. Use list_files to discover files and directories, read_file to read file contents, and search to find text. Do not use run_process for these filesystem inspection operations. Prefer dedicated Git, build, format, analyzer, test, and package tools when available. Output is bounded; execution timeouts are host-controlled—do not supply a timeout argument. Use edit_source for targeted source edits and their reversal. Restoring a whole file with git checkout, git restore, or reset can discard unrelated uncommitted changes; do not use these commands as a substitute for reversing a specific edit. Whole-file restoration requires authorization for that scope and verification that unrelated changes will be preserved. Existing repository .ps1/.sh files are supported as literal file invocations (direct paths, PowerShell -File, or Bash/sh/zsh script operands); the outer shell requires executable permission; commands, interpreters, and scripts require command-policy authorization. Pipelines, shell parameter syntax, file redirection, named variable references, PowerShell scalar variable/environment assignments, and POSIX assignment prefixes are supported when every named command passes policy. Command and script paths must remain explicit; command substitutions, script blocks, and inline interpreter programs remain unsupported. Variable setup and expansion occur in the child shell and do not persist between tool calls.

For custom scripting such as analyzing logs, transforming data, or computing results, use the in-memory C# host (`csharp_script`). Do not write or execute ad hoc Python, Bash, or PowerShell scripts, including inline scripts, for this work. Ordinary CLI commands and pipelines for authorized repository operations remain available through run_process; prefer dedicated tools when applicable. If csharp_script is unavailable and custom scripting is necessary, ask the user to enable it; continue independent work with available tools.
