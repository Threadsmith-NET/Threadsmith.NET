# AGENTS.md — Threadsmith.Tui

## Purpose

Own the conversation-first inline terminal projection and command adapter for interactive sessions.

## Ownership

- PrettyPrompt multiline composer, Spectre.Console output adapter, and TUI-isolated Markdig parser adapter.
- Closed bounded immutable semantic Markdown documents, answer-block collection, terminal-control neutralization, responsive host-owned layout, safe source fallback, capability-gated redirected raw-source items, and serialized output batches.
- TUI-owned semantic text roles and ordered mixed-role segments, immutable theme/style/link data, terminal-native system defaults, four compiled themes, layered configured-theme catalog loading, active theme selection, atomic user-default persistence, and safe PrettyPrompt/Spectre.Console adapter resolution.
- Native-scrollback transcript rendering, unbulleted one-character-indented shared Codex-style lifecycle blocks, batched live events, a responsive composer-adjacent session status row, inline repository workflow, validation evidence, and sequential review prompts.
- Terminal-neutral interaction seams used by `Threadsmith.CoreRuntime.Tests` and `Threadsmith.RepositoryLifecycle.Tests`.

## Local Contracts

- Ordinary terminal output is the transcript. Do not enable application mouse reporting or replace native scrollback selection.
- PrettyPrompt owns only active composer editing, wrapping, clipboard paste, and cancellation. Preserve submitted text exactly, including leading/trailing whitespace and line breaks.
- The composer has no completion source. Do not reserve completion-pane rows: multiline input must scroll only at the bottom of the visible window.
- `Ctrl+V` paste must enter as a complete clipboard operation; do not replay pasted text as synthetic per-character events.
- Mouse selection and terminal keyboard mark mode must copy any prior input or response with the terminal's normal `Ctrl+C` behavior.
- PrettyPrompt and Spectre.Console types remain inside this project and its adapter tests. Flush the active Spectre output writer before releasing the serialized console gate so review/status text is visible before PrettyPrompt begins its next read. `PlanProposed` and `MutationSetProposed` are lifecycle boundaries that end transient activity before their sequential review prompts can acquire the gate.
- Rendering call sites use `TuiTextRole`/`TuiTextSegment`, never literal colors or terminal markup. The compiled `system` theme inherits terminal foreground/background; missing colors fall back through `Default`, while stable system semantic decorations survive unless the exact role explicitly overrides them. All built-ins keep ordinary transcript/composer backgrounds terminal-native, reserve backgrounds for actual highlights, and give the composer prompt and transient `THINKING` indicator distinct foreground-only roles. `NO_COLOR`, redirected output, or capability-limited terminals suppress all styling without changing words or markers.
- Live event batches append exact raw model text through `ConversationTranscript` first. With default `tui:renderMarkdown=true`, contiguous accepted answer deltas collect into a bounded `TuiMarkdownDocument` and render once after one presentation-owned blank line and before the next ordered visible/lifecycle boundary; conventional headings omit their source `#`/setext delimiters and use semantic style plus block spacing, with bounded theme-neutral double/single underline rules for H1/H2; timer-only activity refreshes do not fragment the block. `false` preserves terminal-safe source chunk cadence. Reasoning, tool/MCP, status, diff, historical, and headless projections never enter Markdig. HTML and unsafe links remain inert, parser/limit/cancellation failures use visibly escaped source once, and oversized active blocks atomically switch to escaped source streaming. Interactive document/segment/source items and redirected raw-source items share the console gate; raw-source admission requires the surface's immutable redirected-output capability. Cancellation can reject only pre-gate batch admission: an admitted batch completes non-cancellably, while a rejected buffered batch terminalizes once as source with a non-cancelled token. `THINKING` ends immediately before buffered output becomes visible.
- Live event batches preserve ordered plain text while assigning dedicated roles to user/assistant text, reasoning markers, tool outcomes, plan lifecycle headers/bodies, host path links, validation outcomes, added/removed diff lines, and stable Markdown semantics.
- Theme definitions are loaded whole from each configuration provider before case-insensitive id replacement; numeric array positions never merge fields across layers. Theme ids, colors, and decorations are bounded and validated before reaching Spectre.Console. Raw ANSI/OSC/control characters are not accepted as theme data. Each invalid configured theme is omitted independently while valid siblings remain selectable, and the interactive startup prints a bounded sanitized warning naming the rejected theme and reason. An unknown configured default is reported separately and selects the built-in `system` theme; catalog-wide bound failures still fail closed to `system` with an explicit warning.
- `ConversationTranscript.Apply(IDomainEvent)` is the single live append boundary. `tui:showOperationDurations` defaults on and one immutable snapshot controls request/tool/MCP/semantic-check text; dynamic elapsed updates use injected monotonic time, change text no more than four times per second through the existing serialized console gate, and never create durable ticks. Final tool/MCP/semantic-check duration comes from its owning event boundary, and invalid/missing legacy values are omitted. The composer already displays submitted input, so the transcript does not echo it with a `You:` label. The first visible non-model event after submitted input starts after one presentation-owned blank line; model answers get that separator through answer-block rendering. Reasoning is retained out of the default transcript while transient activity is active (`THINKING` for model work, `TOOLS`/`MCP` for invocation, `SEMANTIC CHECKS` for semantic validation); `THINKING` yields during tool/MCP/semantic-check work, resumes for model continuation after tools, and disappears before final output without a completed transcript marker. Leading whitespace-only model chunks are suppressed. Tool/MCP activity renders one source-appropriate `completed|failed` marker, and live/transcript semantic-check activity correlates starts/completions by run id and semantic-check id before rendering `completed|failed|degraded|skipped|cancelled|unknown` with bounded host-authored detail; neither is assistant answer text. Mutation-proposal start events render a host-authored preparation status/activity before broad hidden preview generation; repair attempts render a host-authored retry status before the hidden correction turn continues. When a start event includes bounded sanitized activity detail, both the live row and completion marker append it in parentheses; the TUI never parses raw arguments itself. Host-authored status and error output retains explicit provenance markers. Subsystems publish host-owned domain events; they never write directly to the terminal.
- `UiEventDispatcher` batches streamed events before output. Do not render model chunks through a character-level redraw loop.
- `/open`, `/trust`, `/help`, `/new`, `/resume`, `/clone`, `/models`, `/auth`, `/mcp`, `/reasoning`, `/thinking`, `/tools`, `/fetch-authorize`, `/context`, `/agents`, `/skills`, `/plan-policy`, `/policy`, `/theme`, `/validation retry`, and `/quit` are host commands. `/new`, direct or selector `/resume`, and `/clone` dispatch one serialized host transition boundary; the TUI never owns active-session authority, and clone confirmation prints a copyable source `/resume` command. `/agents <delegation-id>` inspects the bounded durable run tree; `cancel` and `cancel-child <assignment-id>` route hierarchical cancellation through shared host commands. It never renders raw child transcripts or hidden reasoning. `/skills` lists metadata, refreshes, inspects provenance, verifies, externally enables/disables, pins, invokes typed input, inspects/continues/resumes/cancels durable workflows, and reports only bounded host projections; private skill bodies and raw model payloads never render. `/context mode` reports or changes the durable next-turn conversation mode, `/context inspect` renders the latest host-owned inclusion/omission/provenance/pressure projection, and `/context compact` requests bounded safe-boundary compaction; headless callers use the same commands. `/models` and `/reasoning` dispatch the same host-owned list/current/select/set commands exposed to headless callers. `/mcp` uses only Core lifecycle DTOs through `TuiController`; missing profile/capability ids use numbered selectors, sensitive identity mutations show the exact sanitized profile/endpoint before confirmation, and explicit resource/prompt output retains an `UNTRUSTED MCP` marker plus aggregate host-truncation disclosure when server items were omitted. `/auth openai-codex [login|status|logout]` dispatches the provider-neutral authentication command; provider-specific OAuth remains in App/provider composition, and successful catalog changes require restart because the current session catalog is immutable. They persist the complete repository selection, invalidate stale context occupancy after a change, distinguish selectable levels from always-on/uncontrollable and unsupported reasoning, and durably reset reasoning to `none` when profiles change. `/open` rebinds active model selection and its persistence target before the repository-open workflow completes. `/thinking` and `Ctrl+T` on an empty composer toggle the latest sanitized reasoning view using `<thinking>` tags; no mouse reporting is enabled. `/tools` lists every registered tool through the numbered selector with enabled, category, source, and essential metadata; non-essential selections persist immediately to repository configuration, while essential selections remain read-only. `/theme` selects configured and built-in themes locally through the numbered selector or direct id, reports current state, applies only to subsequent output, and atomically persists `tui.defaultTheme` through a syntax-preserving targeted update that retains unrelated settings, comments, trailing commas, and surrounding formatting. Persistence failure leaves the active selection unchanged; no durable domain state is written, and normal higher-layer configuration precedence remains authoritative at startup. `/help` renders descriptions at one fixed column and moves descriptions for commands that exceed that column to an equally indented continuation line. Unknown slash commands fail locally and must not reach the model; keep routing extensible for later `/model`, `/reload`, and `/resume` commands. `/tools` requires an additional explicit outbound-disclosure confirmation before it records repository-bound `web_search` consent; schema 3 also discloses current-message exact URLs, separate model-proposed approval, and untrusted ingestion, while denial continues the turn without authority. Disabling search revokes consent. An eligible natural-language URL under older schema-2 consent triggers visible revised re-consent before submission. While fetch is already progressively active, the application-owned prompt router invokes one serialized `Deny`/`Approve one attempt` selector showing model provenance, sanitized origin/path, query presence, and digest without query values; approval is exact invocation-only and cancellation fails closed. URL-free prompt lifecycle notifications are queued directly to this live TUI adapter and never published through the shared domain event stream or restored session history. `/fetch-authorize <initial-public-https-url> [redirect-public-https-url ...]` validates the current repository-specific URL-count bound and atomically grants one exact transient invocation chain for the active repository/session without printing URLs or exposing the authorization boundary to the model; malformed or overlong input reports a local error and never escapes the command loop, and separate commands remain separate fetch groups.
- Interactive startup opens the current directory when `--repository` is omitted. Explicit repository, trust, and solution CLI values bypass only their corresponding prompts. A valid remembered `solution.path` auto-selects after trust and prints a repository-relative notification; explicit `--solution` overrides and refreshes memory. Missing memory falls back to normal discovery.
- Before trust/open, startup asks through host-owned initialization commands whether an empty repository should be scaffolded. The composition root supplies the initial pre-runtime-storage `.threadsmith` existence snapshot so its default database cannot suppress the prompt; later `/open` operations use live state. Use a numbered Initialize/Continue selector only when neither `.threadsmith/` nor a supported solution/project exists; confirmation is local, decline is non-mutating, and TUI never performs filesystem scaffolding directly.
- Startup renders the ASCII product wordmark and `Forge better code, not slop.` followed by a blank line, then host-derived model/repository/trust/solution/semantic status. After selecting a solution, show a transient `Semantic confidence: Loading...` spinner until the host publishes its semantic completion fact, then clear the spinner and print the terminal confidence or `Unavailable` for a completed `None` result before showing the composer. Subscribe before repository loading so the confidence or completion result is never missed. Never render credentials or secret references.
- The composer prompt is the sanitized, bounded current repository directory name and changes only after a successful repository open.
- Trust and ambiguous-solution prompts use numbered highlighted choices with Up/Down and Enter. Cancellation fails closed.
- Selecting Cancel from a startup trust, trust-upgrade, or solution menu exits the application before showing or reading the composer. In-session `/open` cancellation keeps the active session and prompt.
- Repository trust exposes inspect-only, read, build, and mutation grants. Build trust warns that repository-controlled code may execute. Invalid or cancelled choices fail closed.
- Structured plans run host sanity checks before review; proposal rendering uses the shared guided lifecycle block, remains decision-neutral while durable approval provenance is pending, and interactive plan review is queued only from an `ApprovalRequested` event whose host-owned kind is explicitly `Plan`; action/display text never determines routing, and legacy unclassified events fail closed. `/plan-policy` may auto-approve valid plans according to the selected policy, but that renders plan-approval provenance and any available concise risk basis through the shared block, only starts governed mutation preparation, and never approves exact diffs or writes. Approving a structured plan starts its governed mutation-preparation pass when a repository baseline is available. Shared lifecycle blocks, including mutation proposal status and applied mutation notices, use unbulleted ` LABEL:` headers with one formatter-owned leading-space indent, and adjacent visible host lifecycle blocks render with exactly one presentation-owned blank line between them. The resulting preview always renders before either a sequential mutation-review prompt or host-authorized policy application; interactive diff projection is compacted to changed hunks with bounded unchanged context and presentation-owned hidden-line markers while preserving added/removed roles and durable canonical full-diff authority. Mutation preparation/retry blocks render attempt and correction-reason detail; applied mutation blocks render policy provenance, affected path, and any available concise plan-derived detail without replacing semantic-check validation evidence. When post-apply validation is configured without the semantic stage, render a validation-start `MUTATION:` block so compile/diagnostics/test waits are not silent. Structured lifecycle previews additionally render operation, source/destination, risk, and case-only status through the same shared projection. Plan approval alone never approves mutations. `MutationSetProposed` is review-ready: the TUI loads its exact staged set through typed session/mutation-set ownership and fails closed if that contract cannot resolve, without polling or depending on execution-checkpoint timing. Policy-auto-approved plans enter the same exact-diff path as manually approved plans. `/plan-policy` lists five plan policy descriptions, warns for trust modes, updates session state, persists every plan policy except `TrustSession` to repository settings, and identity-fences `AlwaysTrustRepo`. `/policy` lists five mutation policy descriptions, warns for trust modes, updates session state, and persists/revokes only `AlwaysTrustRepo`.
- Applying an approved mutation delegates to the shared execution apply-only command: it verifies or captures the durable pre-mutation baseline, records/reconciles write-ahead commit state, applies the exact diff, then resumes post-apply validation through the host boundary before reopening the composer so validation completion, terminal validation failure/cancellation/rollback, or correction status is visible with distinct success/error/warning wording. A correction refreshes controller staging to the new mutation and re-enters the sequential exact-diff review loop; new ordinary submissions are rejected while a correction review is active. Cancellation or transient failure retains the exact post-apply run guard and prints `/validation retry`; that command resumes the retained run and releases the guard only at a terminal or correction-review phase. The TUI does not sequence persistence/workspace/validation itself.
- Discarding a staged execution mutation rolls back private staging, clears the local staged-mutation review state, and cancels the owning run so the completion observer cannot leave the composer blocked or reject later submissions as stale correction reviews.
- Spectre.Console live display is not used concurrently with PrettyPrompt input. The transient reasoning spinner remains active through suppressed leading whitespace, ends before visible answer output is appended, and the next composer does not open until the run-completion transcript batch is rendered. Status-display failures propagate through the shell boundary; they are never discarded.
- The session status surface is composer-adjacent, not permanently pinned: PrettyPrompt 6.0.4 has no public fixed-status API, and cursor-managed pinning would weaken native-scrollback guarantees. Immutable host-derived status, including the current local Git branch resolved through `IGitQueryService` (or `--` when detached, outside the exact worktree root, timed out, removed, inaccessible, malformed, or otherwise unavailable), is serialized through `IConsoleSurface` immediately before each composer, reevaluates terminal display-cell width at that boundary, preserves the model profile display name (without the redundant provider model id) and reasoning in compact rows, reports context occupancy against the selected profile's full configured `ContextWindow` (while inspection separately reports the output-reserved input budget), omits lower-priority segments rather than wrapping, pads non-empty output to the measured window width, and emits nothing when output is redirected. The dedicated `SessionStatus` role defaults to terminal reverse video in every compiled theme so padding and text form one bar without literal color assumptions; style suppression removes inversion. Wholly unobserved provider usage renders `tokens --`; `tokens 0` requires a provider observation. `tui:footer:enabled=false` hides presentation without disabling provider usage accounting.
- Process cancellation is linked into the interactive shell; Ctrl+C cancels active work before the terminal and shared resources are disposed. Cancelling a transient activity display must terminate its refresh loop and release the serialized console gate even when the underlying operation is still pending.
- Structured validation projections render compiler diagnostics plus test pass/fail/skip totals and host-authored selection rationale; raw process output remains outside routine transcript rendering.

- `/hooks` is an additional host command that lists and inspects configured handlers, applies process-local enablement, targets one handler for tests, externally approves/revokes exact repository declarations, and queries bounded audit through shared commands.

## Work Guidance

- Keep interactive behavior as a projection over `TuiPresenter` and `TuiController`; do not move engine state into the terminal adapter.
- Serialize prompt reads and output so background events cannot corrupt the active composer.
- Validate interaction changes in a real Windows Terminal in addition to terminal-neutral automated tests.
