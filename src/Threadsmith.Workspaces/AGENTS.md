# AGENTS.md — Threadsmith.Workspaces

> **Scope:** Repository opening, trust, immutable baselines, transactional file mutation, rollback, and workspace isolation.

## Purpose

Own the safe repository lifecycle and the only host path for applying approved file changes. This project creates host-owned workspace facts for `Threadsmith.DotNet`, keeps staging private, and never exposes Roslyn/MSBuild objects.

## Ownership

- `RepositoryLifecycle.cs` — handlers for repository initialization status/scaffolding, open, solution selection, atomic solution preference persistence/stale cleanup, and baseline capture.
- `RepositoryInitializer.cs` — confined eligibility inspection and idempotent, non-overwriting minimal `.threadsmith/config.json` scaffolding.
- `DotNetEnvironmentResolver.cs` — installed dotnet/SDK/MSBuild resolution and explicitly trusted restore execution.
- `TransactionalWorkspace.cs` — immutable baseline content, copy-on-write text/lifecycle staging, exact add/delete/move/edit preview, source/destination conflict detection, compensating approval-scoped commit, protected rollback, exact-identity reconciliation, command coordination, and mutation telemetry.
- `MutationTransactionObserver.cs` — internal no-op production boundary plus friend-test observation points for deterministic filesystem-effect fault and compensation verification.
- `MutationApprovalPolicyService.cs` — exact-preview risk classification, active-repository policy binding, session policy decisions, invariant mutation guardrails, and confined atomic persistent repository trust.
- `PlanApprovalPolicyService.cs` — active-repository plan approval policy binding, risk-to-policy decisions, session policy changes, configuration provenance, durable policy-change events, and orchestration of persistent plan trust.
- `PlanApprovalRepositoryBinding.cs` — immutable normalized repository root, configuration path, and exact identity used for persistent plan trust.
- `RepositoryPlanApprovalPolicyStore.cs` — confined repository-owned plan policy marker persistence in `.threadsmith/config.json`.
- `UserPlanTrustGrantStore.cs` — user-owned exact repository trust grants for persistent plan approval.
- `PlanApprovalPolicyPersistence.cs` — grant-first persistent-trust writes, downgrade-first revocation, and fail-closed compensation ordering across repository and user stores.
- `GitWorktreeManager.cs` — shell-free Git process adapter for explicit detached worktree creation and removal.
- `GitQueryService.cs` — closed, bounded, local-only diff/log/show/blame/branch comparison with revision/path validation and executable-helper neutralization.
- `WorkerCoordination.cs` — Managed worker leases under the host temporary root, freeze/remove ownership checks, and stale/incomplete/out-of-scope/overlapping worker-package conflict detection.
- Repository lifecycle contracts and DTOs remain in `Threadsmith.Core`; SQLite implementations remain in `Threadsmith.Persistence`.

## Local Contracts

- Trust is ordered: `UntrustedInspection` < `TrustedRead` < `TrustedBuild` < `TrustedMutation` < `FullyTrustedAutomation`.
- Untrusted inspection may load repository configuration and discover candidate solution/project paths, but it cannot select a solution or capture file content hashes.
- `TrustedRead` permits solution/project XML inspection and baseline hashing. SDK probing runs from the installed host directory; it does not allow repository SDK resolution, restore, MSBuild evaluation, analyzers, source generators, build, or tests.
- Restore runs only at `TrustedBuild` or above and records `RepositoryRestoreState`; restore failure remains a fact for semantic-confidence degradation.
- Every selected/configured/approved/referenced path must remain under the normalized repository root. Reject any existing symbolic-link or junction component beneath the root before reading; discovery and baseline enumeration skip nested reparse points and filesystem entries whose attributes cannot be safely read, recording skipped entries in workspace telemetry.
- Baselines hash source and project/build metadata files under configured approved roots, skip `.git`, `bin`, `obj`, prohibited paths, and reparse points, and return repository-relative slash-normalized paths in deterministic order. Prohibited-path globs use `*`/`?` within a segment, `**` across segments, and trailing `/` for descendants.
- Transactional baselines also retain bounded Git revision/status, selected solution/configuration, trust, approved roots, and prohibited paths. Baseline file content is captured asynchronously and cancellably when the transactional workspace is registered, and must stay within the coordinator's configured content-byte limit (256 MiB by default).
- Mutation staging requires `TrustedRead`, 1–100 bounded typed changes, an exact `WorkspaceId` and capture timestamp, unique stable ids, and repository-relative targets. Create requires an absent destination; delete and move require exact baseline SHA-256/byte identities; move requires a distinct absent destination and may carry explicit UTF-8/BOM plus LF/CRLF move-plus-edit content. Both move endpoints pass accepted-plan, approved-root, prohibited/secret/Git/reparse, worker-scope, and collision checks. Staging never changes disk and is invisible to baseline readers; commit separately requires `TrustedMutation`.
- Model-proposed sets stage through `TransactionalWorkspaceCoordinator`, which registers the exact staged review plus workspace/session ownership before publishing `MutationSetProposed`. `GetMutationReviewCommand` therefore resolves the event's typed session/mutation-set identity without depending on later execution-checkpoint persistence; preview, commit, and rollback commands retain the same ownership fence. Execution promotes reconciled repository bytes to a new capture timestamp/hash set after every apply so later correction/plan-step staging detects only external changes; the original diagnostic baseline remains owned separately by validation.
- The coordinator invokes `MutationStaged` exactly once after initial exact-diff staging and before review readiness is published. Mutation approval requests carry the closed `MutationSet` request kind; action text is presentation-only. `MutationSetProposed` preview/toggle events do not own hook invocation; transaction completion is correlated from the ordered per-mutation and approval events into one advisory `MutationApplied` boundary.
- Preview always includes the exact aggregate unified diff. Lifecycle previews explicitly identify add/delete/move, destination, case-only status, and host lifecycle risk; move-plus-edit shows both relocation endpoints and content changes. Each change has a separately configurable `PreviewEnabled` projection flag; disabling an individual view does not remove the change from the aggregate review artifact or recompute it.
- Commit accepts whole-set, selected-file, selected-mutation, or host policy approval. A matching staged approval id is mandatory for every level. `ReviewAll` is the default; `ReviewRisky` classifies exact diff lines plus deletion/config/dependency indicators; `TrustPlan` uses host-recorded accepted-plan scope; session/repository trust modes still require `TrustedMutation`. `AlwaysTrustRepo` is the only persisted approval policy and is loaded from the active repository's `.threadsmith/config.json`; selecting any other policy revokes the persisted value through case-insensitive configuration keys while preserving existing spelling. Policy persistence rejects reparse components before reads and writes and shares `RepositorySettingsCoordinator` with other `.threadsmith/config.json` writers. Hashes, approved roots, prohibited and secret-bearing paths, `.git` metadata, and reparse-point confinement fail closed.
- Lifecycle commit writes private temporary bytes, removes baseline identities, then publishes and verifies final identities so case-only moves remain safe; repository filesystem behavior, not an OS-name heuristic, determines case comparison. Failure compensation ignores caller cancellation, attempts every cleanup/restore effect, and reports aggregate failure when any effect remains incomplete. Reconciliation classifies exact endpoint identities as `NotStarted`, `Applied`, `Compensated`, `Conflicted`, or `Indeterminate`. Rollback removes created/move-destination files before restoring exact modified/deleted/move-source bytes. If any committed endpoint changed afterward, rollback reports a conflict and preserves newer user content.
- Git reads require the opened directory to equal Git's reported worktree root; ancestor-repository discovery is rejected. They normalize documented nullable/defaultable intent fields before validation, host-own diff/show/blame/comparison resource ceilings, and clamp the simple log result hint. They use fixed argument construction, literal pathspecs after `--`, NUL-delimited filename records, raw-byte blob classification, truthful process/output truncation, root-commit comparison, local revisions without embedded path expressions, and disabled pager/color/external-diff/text-conversion behavior. They never perform remote operations or accept arbitrary Git options.
- Raw unified diffs are preview artifacts, not executable model input. Delegated-worker worktrees isolate worker file state but are not sandboxes; only explicitly authorized implementers whose role, mode, and child-run identity match the frozen plan assignment acquire coordinator-owned detached leases at the exact parent revision. Workers never merge themselves, and parent integration rejects rooted/dot-segment worker paths before canonical scope and overlap checks, then fails closed for stale baseline, incomplete identity, scope excess, or worker overlap before normal transactional restaging. Models emit typed text ranges; semantic operations emit full-document text replacements.
- `GetRepositoryTrustCommand` exposes persisted trust through the application boundary so interactive surfaces do not depend on persistence implementations or repeat satisfied trust prompts.
- `RepositoryOpened` and `SolutionLoaded` are emitted through the shared domain event stream. Live Roslyn/MSBuild/configuration objects never cross the boundary.
- Successful solution selection best-effort persists a slash-normalized relative `solution.path` through a same-directory atomic replacement while preserving unrelated JSON and the spelling of existing case-insensitive keys. Its complete read-modify-replace operation shares `RepositorySettingsCoordinator` with model, tool, and mutation-policy preferences so concurrent changes cannot discard one another. Valid memory auto-loads at surfaces, explicit selection overrides it, and a missing file is best-effort cleared before normal discovery. Escape, prohibited-path, malformed, and reparse failures still fail closed.
- Repository initialization is offered only when `.threadsmith/` and supported solution/project candidates were both absent before host runtime storage initialization. Scaffolding rejects reparse roots/directories, writes strict UTF-8 minimal neutral JSON, never includes an empty `tools:enabled` allowlist, and never overwrites existing configuration.
- Opening another repository for a session replaces and invalidates that session's prior in-memory workspace, reloads that repository's mutation policy, rebinds user-grant-backed plan approval by replacing only the repository configuration layer while preserving compiled/machine/user/session/CLI/environment precedence, and redirects persistent policy changes to its confined configuration path.
- Plan approval policy preserves configuration-source provenance: repository content may select every plan policy except session-only `TrustSession`; trusted user/session layers may select session trust explicitly. Persistence writes `ReviewAll`, `ReviewRisky`, and `AutoApproveAllValid` as repository defaults and writes `AlwaysTrustRepo` with an identity-fenced marker plus user-owned grant. `TrustSession` does not rewrite `.threadsmith/config.json`. Reset/revocation inspects persisted policy and user-grant state independently of higher-precedence effective policy, removes the user-owned grant before replacing an identity-fenced marker, and failed persistent trust writes must not leave a user-owned grant capable of activating a later repository marker. Repository marker storage, user-grant storage, binding creation, and cross-store compensation remain separate Workspaces components; the policy service remains the only decision and command authority.
- Dotnet probing and restore drain stdout/stderr while retaining at most 64 Ki characters from each stream, including after process-tree cancellation.

## Work Guidance

- Preserve untrusted inspection as a useful, non-executing mode; do not collapse trust to a Boolean.
- Do not add compiler evaluation or symbol operations here; those belong to `Threadsmith.DotNet`.
- Do not implement semantic edit logic here; `Threadsmith.DotNet` emits host-owned text mutations into this engine.
- Keep baseline capture read-only, cancellation-aware, bounded in parallelism, and instrumented for duration/file count. Deduplicate conflict hashes by normalized path and bound concurrent file reads.
- Treat repository configuration as data. Never interpret config values as executable code.
